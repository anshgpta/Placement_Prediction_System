# PLACEMENT PREDICTION SYSTEM

Placify is a college-project demo with a student portal, an administrator portal, a FastAPI backend, SQLite persistence, and a Machine Learning-based placement-percentage prediction system.

The trained model is **not included in the repository** because the generated model files can be large. Instead, the project includes the training script and dataset required to generate the model locally.

## What is included

- Student signup/login with salted PBKDF2 password hashes (passwords are not stored as plain text).
- Student profile form covering the model dataset's available features: academics, coding/aptitude/communication/reasoning scores, mock interview, projects, internships, certifications, hackathons, GitHub, LinkedIn, backlogs and personal-development fields.
- Placement prediction generated by a locally trained ML model; the result is stored against the student's account.
- Admin login/dashboard with registered-student count, profile completion, predictions generated, average estimate, searchable/filterable student directory, detailed input view and CSV export.
- SQLite database at `backend/placify.db`, created automatically on first startup.
- `backend/train_model.py` for training and generating the required ML model files.
- Supplied student placement dataset used for model training.

## 1. Install dependencies

Open a terminal in the `backend` directory:

```bash
python -m venv venv
```

Windows PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## 2. Generate the ML model

The trained model is intentionally not included in the GitHub repository.

After installing the dependencies, run the training script from the `backend` directory:

```bash
python train_model.py
```

The script will:

- Load the student placement dataset from the `dataset` directory.
- Remove duplicate records.
- Handle missing values.
- Prepare numerical and categorical features.
- Split the data into training and testing sets.
- Train a `RandomForestRegressor`.
- Calculate MAE, RMSE and R².
- Generate the required model files inside the `backend` directory.

The following files will be generated automatically:

```text
backend/
├── placement_percentage_model.joblib
├── placement_model_columns.joblib
├── numeric_defaults.joblib
└── categorical_defaults.joblib
```

You must run `train_model.py` before starting the backend for the first time.

## 3. Start the backend

From the `backend` directory:

```bash
uvicorn main:app --reload
```

Check:

```text
http://127.0.0.1:8000/api/health
```

or open:

```text
http://127.0.0.1:8000/docs
```

## 4. Start the frontend

In VS Code, open the project folder.

Right-click:

```text
frontend/html/index.html
```

and choose **Open with Live Server**.

Do not open HTML files by double-clicking them if the browser blocks local requests.

Frontend pages call the API at:

```text
http://127.0.0.1:8000
```

If your API runs at another address, set:

```javascript
localStorage.setItem('placifyApiBase','http://YOUR_HOST:PORT')
```

in the browser console before refreshing.

Open:

```text
frontend/html/admin-login.html
```

to sign in as administrator.

You can change the seeded admin email/password before the first database is created by setting:

```text
PLACIFY_ADMIN_EMAIL
PLACIFY_ADMIN_PASSWORD
```

environment variables.

If the database already exists, changing these variables does not rotate the existing account password.

For a clean reset of this college-project demo, stop the server and delete:

```text
backend/placify.db
```

then restart it after setting the environment variables.

## Important security and model notes

- This is a local development/college-project baseline, not a production deployment. Before deploying publicly, restrict CORS origins, use HTTPS, add session expiry/rate limiting, rotate the demo admin password, and review privacy/data-retention requirements.
- The API uses a bearer token stored in the browser's localStorage for this demo. Protect devices and avoid using real sensitive personal information.
- The estimate is the trained model's output mapped to a 0–100 range. It is not a guaranteed probability of getting a job and should not be used as a hiring decision.
- The model is retrained locally using the supplied dataset whenever `python train_model.py` is executed.
- The model was trained using the supplied dataset and may have limitations or bias. Validate it with held-out data before relying on its outputs.
- Generated `.joblib` model files should not be committed to the repository. They are created locally by `train_model.py`.
